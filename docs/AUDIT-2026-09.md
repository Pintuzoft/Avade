# Avade – audit September 2026

Review of the whole code base (about 36,000 lines) against bahamut, source code from
[DALnet/bahamut](https://github.com/DALnet/bahamut). The network runs 2.1.4 today, and the
latest release is 2.2.4 (2024-10-04).

**Goal: bahamut 2.2.4**, while still working with 2.1.4, which the network runs today.
Bahamut 3.0 is not released, so part 4 is only information for the future.

- **Part 1** – bugs and compatibility with what you run today (2.1.4).
- **Part 2** – forward compatibility 2.1.4 → 2.2.4.
- **Part 3** – new functionality that services need to use what the ircd offers.
- **Part 4** – Bahamut 3.0 (Gossip + IRCv3), not released: information only, nothing we build for now.

Status: [ ] = not fixed, [x] = fixed (1–12 `security-fixes`, 26–32 `topic-sync`, 68 `charset-utf8mb4`, 51 `nickipstr`, 17/59/N0/N1/69 `vop-hop`, 13/70 `sessions`, 14–16 `reconnect`, 45/47 `stability`, 24/33–44 `functional-fixes`, 19–21/23/71 `bans-and-matching`, 22/25/49/50/72/73 `cleanup`, N14 `vhost`, N2 `svsclone`, 52/N5/74 `chanflags`, N6/N7 `spamfilter-svstag`). Line numbers refer to commit `511c0db`.

> Note: `Handler.process` catches every `Exception`. An NPE or AIOOBE therefore does
> not crash services, but the command is aborted silently (the user gets no reply) and sometimes
> the state is left half updated.

# PART 1 – Bug fixes & compatibility with 2.1.4

## 1.1 Access & security (highest priority)

- [x] **1. Users with access can make themselves SOP, even if they are AKICKed.**
  [CSExecutor.java:1992](../src/chanserv/CSExecutor.java#L1992)
  - The condition `!ci.isAtleastSop(ni) && !ni.is(ni2)` lets actions on oneself through, and the level check (line ~1998) is then skipped.
  - `ChanInfo.getNickByUser` (345–377) also returns nicks that are only on the AKICK list.
  - Result: `SOP #chan ADD <own nick>` promotes the user, and the AKICK entry is removed via `removeFromAll`.
  - Fix: allow the self exception only for `DEL`, and require at least AOP.
- [x] **2. ACCESSLOG does not require identify (regression in 511c0db).**
  [CSExecutor.java:1928](../src/chanserv/CSExecutor.java#L1928)
  - `NickServ.findNick(user.getName())` is used instead of `ci.getNickByUser(user)`, and `ni.isAtleast(SA)` instead of `user.isAtleast(SA)`.
  - Someone using an AOP or staff nick without identifying can read the access log, while an SA who is identified under another nick is denied.
- [x] **3. TOPICLOG has no access check.** [CSExecutor.java:1634-1668](../src/chanserv/CSExecutor.java#L1634), 1940–1952
  - The config says SA level, but `ChanServ.enoughAccess` is never called, so anyone can read the topic history of any channel (including +s/+p).
  - `return` is missing after "Database not available".
  - The SYNTAX_ERROR branch dereferences a null `getChanInfo()`.
- [x] **4. NEVEROP is ignored on join.** [ChanServ.java:284](../src/chanserv/ChanServ.java#L284)
  - `ni.is(NEVEROP)` compares the nick name with the string "NEVEROP". It should be `ni.isSet(NEVEROP)`.
- [x] **5. DYNAOP (new feature) lacks checks.** [ChanServ.java:861-925](../src/chanserv/ChanServ.java#L861)
  - `findNick(user.getName())` does not check identify, neither for the user who ops nor for the user who is opped.
  - It bypasses NOOP.
  - `addAccess → removeFromAll` silently removes an AKICK entry.
  - An AOP can deop another AOP and so remove it from the list.
- [x] **6. Throttle is broken.** [Throttle.java:79](../src/core/Throttle.java#L79)
  - The expression `- this.lastHit < range*1000` is missing `now()` and is therefore always true.
  - An early `return` when `hits > maxhits` updates `lastHit` before the reset code is reached, so the lock becomes permanent. Anyone can lock a nick or a channel out of IDENTIFY until restart.
  - Successful attempts are counted too.
  - GHOST ([NSExecutor.java:1132-1150](../src/nickserv/NSExecutor.java#L1132)) has no throttle at all, so passwords can be brute-forced.
  - IDENTIFY/DROP with one argument (line 1099: `!ni.is(user)` is always false) is never throttled.
  - Fix: `now() - lastHit`, reset before the early return, count only failed attempts, and throttle GHOST and DROP.
- [x] **7. Passwords leak in plain text to the snoop channel.**
  - CS DROP ([CSExecutor.java:473-501](../src/chanserv/CSExecutor.java#L473)) masks only on a successful attempt.
  - CS REGISTER (347–375) leaks on all error paths.
  - NS DROP masks only when `cmd.length == 5`.
  - Fix: mask before `validateCommandData`.
- [x] **8. Every raw IRC line is written to stdout, including `IDENTIFY <password>`.** [Handler.java:180](../src/core/Handler.java#L180)
- [x] **9. RootServ never checks `enoughAccess`.** Any SRA can add and remove SRAs, even though the text says that only master may do that. [RSExecutor.java:131-181](../src/rootserv/RSExecutor.java#L131)
- [x] **10. Passwords are stored reversibly.** `AES_ENCRYPT` is used with a shared key (SECRETSALT), and GETPASS shows the whole history in plain text.
  - **Fixed (1.2609-8):**
    - Passwords for nicks and channels are stored as PBKDF2-SHA256 with a separate salt per password and 210,000 iterations (`security.Hash`, available in Java, no new library). It takes about 70 ms per check. The number of iterations is stored in the hash, and an older hash is redone at the next successful IDENTIFY.
    - The migration decrypts with secretsalt and hashes in parallel. Old passwords and rows for dropped nicks are removed. If not a single password can be decrypted (wrong secretsalt), the upgrade stops before anything is changed. The step can be run again.
    - GETPASS is removed from NickServ and ChanServ, and NINFO shows no password.
    - New: `/NickServ RESETPASS <nick>` mails a code to the confirmed address, and `RESETPASS <nick> <code> <new>` sets a new password. The code is valid for 2 hours and can only be used once. A new code can be sent no sooner than 15 minutes later, and a wrong code counts as a failed IDENTIFY.
    - New: `/NickServ SETPASS` and `/ChanServ SETPASS` for staff (`setpass` under csop). Staff at the same or a higher level cannot be changed. The event is logged and sent as globops, and everyone who is identified to the nick or channel loses their identification.
    - New: `/ChanServ SET #channel PASSWD <new>` for the founder.
    - Auth codes in mail come from `SecureRandom` instead of md5 of the time. `Hash.md5` is removed.
    - secretsalt is still needed, since the mail addresses must be readable to send mail.
  - Suggestion: bcrypt/argon2 with migration, and remove GETPASS.
  - `Hash.md5` uses a shared static `MessageDigest` (not thread safe) and drops leading zeros.
  - Auth tokens are md5 of the time instead of `SecureRandom`.
- [x] **11. DEOP had no level check: an AOP could deop SOP and founder.** (MDEOP already had the check.) Fixed at the same time: NICK_NOT_PRESENT in OP/DEOP crashed.
- [x] **12. NS DROP ignores MARK** (CS DROP checks it).

## 1.2 Core & protocol

- [x] **13. Persistent sessions/services ID do not work.** [Handler.java:1018-1020](../src/core/Handler.java#L1018)
  - `sidList` is `HashMap<BigInteger,…>` but is looked up with a `HashString`, so `findSid` always returns null.
  - New SIDs created in `doNick` are never registered in the map.
  - **Fixed on `sessions`:**
    - `findSid` looks up the right key.
    - New SIDs are registered.
    - `sid.addUser()` is called, so active SIDs are not purged after a day.
    - `+r` from the ircd is trusted for the current nick.
    - Tested: after a services restart, users are still identified, and the founder is no longer deopped by OPGUARD.
    - `deleteUser` always removes the user, even if the cleanup fails (part of #23).
  - Remaining: the `servicesid` table gets a new row per connection and identify, and is never purged in the database.
- [x] **14. Reconnect on `ERROR :Closing Link` is never triggered.** [Handler.java:1560](../src/core/Handler.java#L1560)
  - `sub1 == CLOSING` compares references. It should be `.is()`.
- [x] **15. Reconnect keeps old state.** [Proc.java:138-143](../src/core/Proc.java#L138)
  - `uList`, `cList` and `sList` are never cleared, so there are ghost users and duplicate servers.
  - `ServSock` calls `System.exit(1)` if the hub does not answer on reconnect, instead of trying again.
  - The old socket is not closed.
- [x] **16. Remote SQUIT, KILL, KICK and MODE from servers are ignored.** The server branch in [Handler.java:196-218](../src/core/Handler.java#L196) does not handle them.
  - On a netsplit, users and servers stay in memory.
  - On a collision kill, ghost users are left behind.
  - **Fixed on `reconnect` (14–16):**
    - `ERROR` from the hub and ping timeout close the link, and a dead link (EOF) is detected at once.
    - Avade tries again every 30 seconds. It no longer exits when the hub is down.
    - On a new link, users, channels and servers are cleared, and the services are introduced again without reloading registered nicks and channels. A reload would create new objects that identified users do not point to, so founders would be deopped.
    - Remote `SQUIT`, `KILL`, `KICK` and `MODE` from servers are handled.
    - Tested against a real network (leaf, hub and services): the hub dies and comes back, an oper runs SQUIT on services, and a leaf splits.
- [x] **17. `Chan.chMode` only consumes parameters for `o` and `v`.** [Chan.java:175-220](../src/channel/Chan.java#L175)
  - With `+bo mask nick`, the mask is taken as the op target, and then an NPE follows on `u.isAtleast`.
  - `cmd[4+m]` is read for every mode character, which gives AIOOBE on for example `+ot Bob`.
  - It affects DYNAOP directly.
  - Fix: a table of which modes take a parameter (`b k l e I j o v`, and `-l` without), a bounds check, and look up the user only for `o` and `v`.
- [ ] **18. SJOIN burst gives duplicate channels per user.**
  - The Chan constructor runs `addUserList(data,6)` and then `doChan` runs `addUserList(data,5)`.
  - `User.addChan` has no duplicate check.
  - `+k` and `+l` make the key and the limit get read as nicks.
- [x] **19. Three bugs in the clone trigger.** [Handler.java:509/525](../src/core/Handler.java#L509)
  - `parseInt("30m")` fails, and as a result the AKILL lasts **3 min** instead of 30.
  - The range trigger bans the IP instead of the range.
- [x] **20. Int overflow in expiry time.** `amount*multiply*1000` is computed as an int, so `AKILL … 30d` gets an expiry date in the past.
  - Applies to [Handler.java:1503](../src/core/Handler.java#L1503) and 1430. Fix: `1000L`.
- [x] **21. StringMatch compiles users' nick, host and gcos as regex.** [StringMatch.java:43-66](../src/core/StringMatch.java#L43)
  - Nicks like `{Bob}` or `Bob[` throw PatternSyntaxException, so akill and sgline searches are aborted.
  - A gcos `*` matches everything, and `.` overmatches in IP addresses.
  - Fix: `Pattern.quote` and no reverse matching.
- [x] **22. DBChanges: NPE if the DB is down at startup** – `getDBVersion()` returns null and `dbver.split` crashes ([DBChanges.java:29](../src/core/DBChanges.java#L29)). *(Corrected: the migration itself works – the switch falls through on purpose and runs all steps after the current version.)*
- [x] **23. Crashes on unexpected input:**
  - `doPrivmsg` without `@` in the target (line 349).
  - The OperServ branch is missing `isUp`.
  - `doSJoin` null check (line 692).
  - `doGlobOps` runs on *all* GLOBOPS (line 753).
  - `deleteUser` when the server is unknown (line 958; the user stays forever).
  - The `Server` constructor when the uplink is unknown or the line is short.
  - `cutArrayIntoString` (`<` should be `<=`).
- [x] **24. `HashString.is(NickInfo/User/Chan)` compares BigInteger with `==`,** so it is always false, for example in [NSExecutor.java:1028](../src/nickserv/NSExecutor.java#L1028).
- [x] **25. Nick hashing does not follow the ircd.** *(Corrected: bahamut uses `CASEMAPPING=ascii`, not RFC1459. Now only `a–z` is converted, independent of locale settings, so `#kåffe`/`#KÅFFE` are treated as two channels, just like in the ircd.)*
  - `toUpperCase()` depends on the locale (Turkish i/I).
  - `{}|` = `[]\` is not applied.

## 1.3 Topic sync (nick & time)

- [x] **26. Colon bug (confirmed in test).** `Topic` does `replace("^:", "")`, which is literal and not regex.
  - The topic is saved as `:hej`, sent as `TOPIC #c nick ts ::hej`, and on the network it becomes `:hej`.
- [x] **27. Only one channel gets its topic at startup.** [CSDatabase.java:1045](../src/chanserv/CSDatabase.java#L1045)
  - `(select … from topiclog order by stamp desc limit 1)` gives one row for the whole network.
  - Other channels get a `Topic` with null values, so `TOPIC #channel null 0 :null` can be sent.
- [x] **28. The wrong time is saved.** `addTopicLog` saves `getTimeStr()` (when Avade received the topic, in the local time zone), not the IRC ts.
  - Fix: save `FROM_UNIXTIME(ts)` and read `UNIX_TIMESTAMP`.
- [x] **29. Wrong setter.** `user.getString(FULLMASK)` is used instead of `data[3]`, which bahamut sends.
  - It can show a real host for hostmasked users.
  - bahamut's "same topic" check never matches.
- [x] **30. The topic is sent on every join, regardless of KEEPTOPIC.** `doSJoin` calls `sendTopic`, and `doChan` also sends it twice when the channel is created.
  - Services are U-lined, so bahamut always overwrites (no TS check). Newer topics are reverted, and people see "ChanServ changed the topic".
  - Fix: send only when the channel is created and KEEPTOPIC or TOPICLOCK is on, and when TOPICLOCK denies a change.
- [x] **31. `checkTopic` gives an NPE** when TOPICLOCK is on and no topic is saved.
- [x] **32. Server TOPIC (burst, after split) never updates ChanInfo.**

> The topic fixes are tested against real bahamut 2.2.4 + MySQL 8: the topic is saved without a colon
> and with IRC time, no TOPIC is sent on join, KEEPTOPIC restores with the original setter
> and time, the burst does not overwrite newer topics, every channel is loaded with its topic after
> restart, and TOPICLOCK restores. TOPICLOG now shows the latest 100 (it used to show the oldest).

- [x] **68. Character encoding: åäö/emoji cannot be saved (found during testing).**
  - Avade reads the socket with Java's default character encoding (UTF-8 from Java 18), but all tables are `latin1`.
  - Latin1 bytes from older clients become `�`, and characters outside latin1 (emoji ☕ etc.) cannot be stored. MySQL then rejects the whole write: *Incorrect string value* (topic, memo, descriptions, snoop log …).
  - The failed entry also stays in the work queue and is retried over and over (see #46).
  - **Fixed on `charset-utf8mb4`:**
    - IRC lines are decoded as UTF-8, with cp1252 as a fallback for old latin1 clients, and are always written as UTF-8.
    - JDBC uses `utf8mb4`.
    - DB 1.2609-2 converts all tables to `utf8mb4_swedish_ci`, after the AES columns (`chan.pass`, `passlog.pass`, `maillog.mail`) are first changed to `varbinary`, so that encrypted passwords and mail are kept byte for byte.
    - Tested on MariaDB 10.8.8 with latin1 as default: both an upgrade of existing data and a new install.
    - Remaining: entries that fail permanently should be dropped or logged (#46).

- [x] **69. UNBAN/INVITE/WHY counted AKICK as access** (found during the VOP/HOP work).
  - `getNickByUser` also returns nicks on the AKICK list, so an akicked user could UNBAN and INVITE themselves past their akick.
  - Now UNBAN and INVITE require AOP+ (as in the ircd, where only ops may remove bans and invite), and WHY requires VOP+.
  - Also: AKICK WIPE and wiping mask entries never cleared the database, so the lists came back after restart.
- [x] **70. Master is set only on `LUSERSLOCK`** (`doFinishSync`), which bahamut sends only from hubs.
  - If Avade links to a server without the hub flag, master is never set, and `sendSpamFilter` does not run either.
  - Fix: run it when the sync is done (second PING, see `Handler.isSynced()`).

- [x] **71. SQLINE and SGLINE ADD have never worked** (found during testing).
  - The validation required `nick!user@host` for all ban types, but SQLINE is a nick or channel pattern and SGLINE a realname pattern.
  - `expireToDate` also ignored the time unit completely: `30d` became 30 minutes, `1h` became 1 minute, and spamfilter akills therefore lasted 30 minutes instead of 30 days.
  - **Fixed on `bans-and-matching`:**
    - One shared parser for durations (number = minutes, or `m`/`h`/`d`/`w`/`y`, in `long`).
    - Safe wildcard matching (escaped, case-insensitive, and one way only when user data is compared).
    - The range trigger bans the range.
    - Tested live: SQLINE on `{Bob}` and AKILL for 60 days.

- [x] **72. Avade started even if nicks and channels could not be loaded.**
  - The loaders gave an empty or partial list on error. Avade still linked, removed `+r` from everyone, changed people to Guest nicks and deopped. `fixMaster` also tried to create the master nick again.
  - **Fixed on `cleanup`:**
    - Avade waits for the database before linking.
    - If loading fails, Avade is passive: no `-r`, no Guest nicks, no deop, kick or modelock, no DYNAOP, no topic changes and no `fixMaster`. NickServ, ChanServ and MemoServ reply "loading".
    - New attempts are made every 30 seconds, and after that services IDs are applied and all users and channels are checked.
    - Tested live by renaming the `nick` table: no deop and no Guest changes. When the table came back, everything was loaded, and the founder was still identified.

- [x] **73. Web AUTH with a wrong code counted as successful** (found during testing).
  - `NSDatabase.authMail`/`authPass` returned `true` whether or not the code matched.
  - The database was not changed, but Avade sent "verified" and logged AUTHMAIL. With PASS, everyone on the nick also lost their identification.
  - Now the updated rows are counted.

- [x] **74. Chanflags did not survive a restart** (found during #52).
  - In the CSFlag constructor, NO_QUIT_MSG got the value from NO_PART_MSG, EXEMPT_WEBIRC was overwritten by HIDE_MODE_LISTS, and NO_NICK_CHANGE by NO_UTF8.
  - CSChanges did not track MAX_INVITES, MAX_MSG_TIME, NO_QUIT_MSG, EXEMPT_WEBIRC, HIDE_MODE_LISTS, NO_NICK_CHANGE and NO_UTF8, so they were never saved.
  - MAX_MSG_TIME validated the flag name instead of the value, and MAX_INVITES gave no reply.
  - **Channels were registered with `max_invites = 0`, which after a restart was sent to the ircd and turned off the `+I` list.** DB 1.2609-5 fixes existing channels.
  - Tested against the ircd with `CHECK CHANNEL` after restart.

- [x] **75. IDENTIFY on a newly registered nick gave a NullPointerException** (found by the test suite).
  - A `NickInfo` created at REGISTER never got an `Expire` object; it was only set when loading from the database.
  - The password was accepted, but "last used" and the session (services ID) were not saved until after the next restart.

- [x] **76. The confirmation code could be shorter than 32 characters** (found by the test suite).
  - `Hash.md5` dropped leading zeros, so about every 16th code was 31 characters or shorter.
  - The code still worked in `/NickServ AUTH`, but a web page that requires 32 characters rejects it.

- [x] **77. New nicks were written to the database one per minute.**
  - This also applied to nick changes, mail confirmations and drops. If Avade was killed in the meantime, the rest was lost.
  - Now five per minute, like channels and logs.

- [x] **78. The master role did not take effect until after a restart if master was offline at sync.**
  - `fixMaster` set the role in the database but not in memory.

- [x] **79. Topic `null` set by `null` stayed on the network** (found on avadedev).
  - Older versions sent `TOPIC #channel null 0 :null` for channels without a saved topic.
  - The new version does not send it, but would have saved the hub's `null` as the channel's topic.
  - Now it is recognized, not saved, and cleared from the channel (or replaced with the real topic).

- [x] **80. A plain `kill` lost everything that was waiting to be written to the database.**
  - Avade now catches SIGTERM/ctrl-c and stops as with `/RootServ STOP`: pending changes are written first.
  - `avade.sh` (start, stop, restart, status, check for cron, log) is installed by `./make.sh install`.

## 5.1 Fixed

**RootServ / MemoServ / GuestServ**
- [x] `/RootServ PANIC` without arguments gave infinite recursion and took down services. The same happened 15 minutes after `PANIC OPER` and after STOP.
- [x] `SRA ADD/DEL` only wrote to the database. Now memory is changed at once, the same way as `OperServ STAFF`. DEL removes only one SRA, and ADD does not touch master.
- [x] An unknown RootServ command gave no reply. `SRAW` without arguments sent an empty line.
- [x] MemoServ `READ` showed the recipient as the sender. `LIST` showed `null` or 1970 as the date.
- [x] `READ`/`DEL` with anything other than a number gave two error messages. A memo over 256 characters is denied with a clear message.
- [x] The guest nick change could hit the wrong user if the first user had disconnected and someone else had taken the nick.
- [x] The master nick's first password had only 9,800 possible values. It is now truly random and is shown to master.

**ChanServ**
- [x] AKICK and RESTRICT did not kick if no one in the channel was identified (`Chan.nickIsPresent` compared oper access). The kick reason was never sent.
- [x] An AOP could move a mask from the SOP or AOP list to VOP/HOP.
- [x] FREEZE/CLOSE/MARK/HOLD/AUDITORIUM removed all hyphens from the channel name and hit the wrong channel.
- [x] `isFounder` and access lookups compared `Object.hashCode()` instead of the name.
- [x] `SET MAILBLOCK` had no effect (two different constants, MAILBLOCK and MAILBLOCKED). This also applied to NickServ.
- [x] REGISTER from an unidentified nick, INVITE with VERBOSE, LISTOPS on a frozen channel, `UNBAN #channel nick extra` and AKICK ADD on an empty channel gave an internal error.
- [x] `SET <option>` with anything other than ON/OFF meant OFF. `SET TOPICLOCK OFF` gave a truncated text.
- [x] Every mode change on a registered channel sent an empty `MODE #channel 0 :+-`.
- [x] Access masks became regex without escaping special characters (`.` matched anything). Broken masks gave an internal error. IP masks were compared against the host name with DNS lookups in the main loop.
- [x] `DEL` followed by `ADD` of the same nick within a minute removed the row from the database. All access entries were written to the database again at every start.
- [x] WHY did not show access via a mask. A cleared topic was not saved. A dropped channel left its topic log for the next owner.
- [x] A new channel had KEEPTOPIC/IDENT/OPGUARD off in memory but on in the database. Now they are on in both, as the code intended.
- [x] The topic stamp at registration was set in milliseconds.

**NickServ**
- [x] `SET EMAIL` and `SET PASSWD` never sent a confirmation mail. The mail is now sent when the code is saved, also at REGISTER.
- [x] Passwords leaked to the snoop channel with `SET EMAIL <password> <mail>` and with `SIDENTIFY` with extra words.
- [x] AUTH of a new password did not unidentify anyone. REGISTER, SIDENTIFY and GHOST did not keep the identification across a restart.
- [x] GETPASS, GETEMAIL and DELETE on an unregistered nick gave an internal error. DELETE can no longer remove staff at the same or a higher level.
- [x] Passwords over 63 characters made the nick unusable. INFO showed the host mask to everyone regardless of SHOWHOST.
- [x] AUTH of a mail address on IRC did not give `+r`. GHOST on yourself killed you. A throttled user got "wrong password".

**OperServ**
- [x] `AKILL ADD nick!*@host` counted matches on the nick but banned the whole host. The nick part must now be `*`.
- [x] JUPE on a linked server, on services' own name or with invalid characters disconnected services.
- [x] IGNORE with a time limit never expired. Broken masks in AKILL/IGNORE/MAKILL gave an internal error.
- [x] FORCENICK and the SQLINE nick change left a ghost entry in the user list.
- [x] `SGLINE LIST` was always empty. `SERVER DEL` never worked. New servers only showed up after a restart. SINFO could not be reached.
- [x] `AKILL DEL *` removed the first ban it found. A user with realname `*` was killed by any SGLINE.
- [x] MAKILL never showed syntax errors and sent errors as GLOBOPS. UINFO listed the oper's own channels.
- [x] VHOST had no rank check. Several database methods closed the wrong ResultSet.

**Core**
- [x] QUIT/NICK/MODE/PART from an ignored user was dropped, so the network state became wrong. Now only PRIVMSG is ignored.
- [x] `JOIN 0` was not handled. `AWAY` without text and unknown senders gave stack traces in the log.
- [x] `services.log` was written without line breaks and without flush.
- [x] Errors in `services.conf` on REHASH killed services without saving. Starting with a broken config now gives a clear error.
- [x] MOTD/VERSION/INFO for the stats server replied as services, and gave an internal error for other targets. SHOWCONFIG gave an internal error.
- [x] The main loop could spin at 100% CPU without a link.
- [x] HashString is created about 20 times faster, with the same codes.
- [x] Debug output removed (`bits:`, SQL queries, `debug(2)`, etc.).

**Second round**
- [x] Memos stayed when a nick was dropped and went to the next owner of the nick. DB 1.2609-7 removes the ones that are still there.
- [x] A service that is killed with KILL is introduced again at once.
- [x] Avade pings the hub after one minute of silence instead of only waiting for a timeout.
- [x] Spamfilter: all flags must be valid, and the pattern must have at least four characters besides wildcards. Spamfilter akills respect the whitelist.
- [x] The whitelist also stops a ban with wildcards that covers a whitelisted address.
- [x] 13 lookups built a new HashString from a name that already existed as one.

**Decision 2026-10-06**

# PART 4 – Bahamut 3.0 (Gossip + IRCv3) – future

Source: branch `bahamut-mods-gossip` in DALnet/bahamut (34 commits, 2026-03-12 → 2026-07-23,
version 3.0.0 in patchlevel.h). **Not merged, not tagged, not released.** The latest release is
still 2.2.4.

**What it is:**
- **Gossip:** a new server-to-server protocol where the servers form a mesh instead of hub/leaf. Each event (`GEVENT`) gets a unique ID and is sent to all peers. There are no cascading splits, and when a peer disappears, its users stay.
  - The links require TLS and a shared password (`gopeer {}`).
  - Conflict rules: the oldest TS wins for nicks, the newest `topic_time` wins for topics.
- **TS5 bridge (`m_legacy_bridge`):** old `connect {}` links still work, and **services connect via TS5 + U:line as today**.
- **IRCv3:** about 20 capabilities, among them account-tag/notify, extended-join, chghost, server-time, message-tags, chathistory, resume, MONITOR, STARTTLS and WebSocket.
- **Built-in services were built and then removed**, in favour of external services such as Avade.

**Checked in the source code – this affects Avade:**
- [x] **B1. CAPAB is removed.** BURST, UNCONNECT, **NICKIPSTR** and NOQUIT are forced on all links.
  - NICK therefore **always sends the IP as a string** (`1.2.3.4`, IPv6 or `0.0.0.0`).
  - **Avade cannot accept a single user**, since `Long.parseLong(data[9])` in [User.java:63](../src/user/User.java#L63) throws.
  - The same fix as #51, so do it once and do it right.
- [ ] **B2. The TOPIC setter is always `nick!user@host`.** See #29.
- [ ] **B3. NOQUIT:** no QUIT per user on SQUIT, so services must remove the users behind the server themselves. Tied to #16.
- [x] **B4. Users from gossip nodes** come via the bridge with IP `0.0.0.0`, servicestamp `0` and umode `+`.
  - The clone trigger and the akill logic must ignore `0.0.0.0`, otherwise Avade can AKILL `*@0.0.0.0` and hit all such users.
- [ ] **B5. The line length** is still 512 to services (2048 only applies between gossip nodes).

**Current limits in the ircd** (not Avade's fault, but good to know):
- SVSNICK, SVSMODE, SVSHOST, SVSHOLD, SVSXCF, SF, SVSCLONE and SJR are **not** spread over gossip.
- NOTICE from services does not reach users on other gossip nodes.
- `+r` from services is not spread.
- In a mixed mesh, services therefore only work fully for users on the node that services are linked to. This should be reported upstream.
- **SASL does not exist** on the 3.0 branch. An early draft exists on the branch `ircv3-support` (2025): `AUTHENTICATE` is sent to a SaslServ alias, and services reply `SASL … SUCCESS|FAILED`. It does not compile and is not merged.
- **Account names:** account-tag, account-notify and extended-join are announced but are always empty. There is no command for services to set an account (`account_name` is never written).

**Opportunities for Avade** (when or if upstream defines the protocol):
- N10: SASL PLAIN/EXTERNAL (SaslServ).
- N11: account names (propose to upstream, e.g. `SVSACCOUNT` or `SVSMODE nick ts +r <account>`).
- N12: CERTFP login, where the fingerprint is shown in WHOIS (numeric 276).
- N13: SVSHOST now gives chghost to IRCv3 clients.
